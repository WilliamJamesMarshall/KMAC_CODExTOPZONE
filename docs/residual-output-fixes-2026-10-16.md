# 잔여 14건 출력 오류 후속 수정

사용자 판정 기준은 모든 추천 업무에 공급기업이 한 곳 이상 있고, 01·02·03의 필수 출력값이 모두 있는 경우에만 정상이다. 공급기업 기능이 실제로 맞지 않거나 외부 홈페이지에 접근할 수 없는 경우를 설명문으로 채워 정상으로 만들지 않는다.

## 변경 내용

- AX 검증에서 근거·과업·데이터 정직성·안전 범위가 통과하고 효과 인과성만 실패한 후보는 설명·업무 변화·효과·KPI만 한 번 수정하고 재검증한다. 원래 기능·자료·분석 단계·결과·근거는 코드에서 고정한다. 다른 원인의 탈락은 유지한다. 수정 호출 장애가 이미 통과한 다른 업무를 버리지 않게 한다. 원본·수정·검증 차원을 내부 진단에 남긴다.
- 공급기업별 원천 기능, 고유 도메인 제약, 지원하는 업무 단계, 상담 확인조건을 별도로 감사한다. 일반 플랫폼의 업종 경험 미확인을 기능 불일치로 단정하지 않는다. 임상 해석·항체 발굴 등의 전문 기능은 원천 설명에 없으면 인정하지 않는다. 모든 입력 쌍의 채택·탈락 이유와 미완전 응답을 기록한다. 후보를 최대 12곳까지 준비하고, 업체가 없는 업무에 한해 3곳씩 추가 검토한다. 표시 한도는 업무당 3곳이다.
- 로그인·계정·고객 리뷰·상품 문의 페이지를 기업의 사업 근거에서 제외한다. 추적 조회 매개변수를 정규화하고, 템플릿 매크로를 근거에서 제거한다. 판매 화면은 판매 기능의 근거로만 쓰며 제조·연구 수행을 추정하지 않도록 한다. 이동 후 같은 페이지가 중복되거나 실패 링크가 반복되어 수집량이 늘지 않도록 방문 한도도 둔다.
- 검증한 대표 도메인 관계만 페이지 이동에 적용한다. 공인 IP·인증정보·포트 검사와 도착지 robots 검사는 유지한다. robots 이동은 본문 이동과 분리해 공개 주소 사이의 이동을 허용한다.
- robots 403·404·410은 공개 페이지 접근을 허용하는 제품 정책을 선택했다. 실제 페이지의 인증·403 응답 또는 명시적인 Disallow를 우회하지 않는다. 5xx는 한 번만 재시도한 뒤 `robots_unreachable`로 중단한다. 성공적으로 읽은 정책만 메모리에 최대 한 시간·128개 저장한다. 만료된 정책으로 실패를 우회하지 않는다. DNS의 일시적 EAI_AGAIN만 한 번 재시도하며 주소가 없는 도메인의 IP를 추측하지 않는다.
- 렌더러는 허용·차단 요청 모두를 자원 한도에 포함한다. 활성 요청 180개·25초·전체 20MB 및 동일 URL 읽기 3회의 한도를 둔다. 이미지를 외부에서 읽지 않고 투명 대체 이미지를 제공해 onerror 반복을 막는다. 차단된 텔레메트리의 재시도는 외부 전송 없이 빈 응답으로 끝낸다. 로그는 URL별 횟수로 집계한다. 종료 중 대기 요청이 추가 네트워크 읽기를 수행하지 않게 한다.
- 단블의 실제 공개 화면에서 관찰된 GET 콘텐츠 경로 세 개만 예외로 허용한다: `https://production-api.danble.co.kr/api/contents/get-all-banner`, `/api/contents/live-item-list/1`, `/api/v1/home2/feed`. 각 경로도 DNS·robots·시간·용량 검사를 거친다. 로그인·좋아요·인증·분석 서비스와 임의 하위 도메인은 포함하지 않는다. 브라우저는 계속 오프라인이며 검증해 읽은 응답만 전달한다.
- 분석 실패도 입력 주소·처리 단계·오류 코드·확인 시각·확인 조치를 담은 별도 진단 PDF를 제공한다. 성공한 기업 분석 보고서와 제목·파일명·버튼을 구별한다. 이전 검색의 결과와 다운로드 상태를 새 검색 시작 시 비운다. 실패 전 검증한 기업 이해가 있으면 부분 결과임을 표시한다. 진단 기록에는 원본 HTML·비밀 설정·쿼리 값·연락처를 넣지 않는다.

## 도메인 관계 확인 근거

2026-10-16에 기존 홈페이지의 실제 이동과 도착지의 기업 식별 문구를 읽어 확인했다. 원본은 `reports/output-root-cause-20261016/residual-collection-probes/`에 보존했다.

| 입력 도메인 | 대표 도메인 | 도착지 근거 |

| cellico.com | eyecane.com | 기존 사이트의 HTTP 이동과 공식 페이지의 Cellico·EyeCane AR Glasses 문구 |

| os2019.co.kr | os-semi.com | 기존 사이트의 `document.location.replace` 주소와 도착 서버가 robots 경로에 반환한 오스·Os Corporation·반도체 장비 제조 설명. 도착지의 HTML robots 응답은 유효 정책으로 간주하지 않는다. |

robots 처리 기준: [RFC 9309, §2.3.1·§2.4](https://www.rfc-editor.org/rfc/rfc9309.html). 4xx에서 본문 접근을 허용하는 것은 표준에서 허용하는 선택이며 강제 규칙은 아니다. 5xx와 연결 실패 시에는 수집을 중단한다. 본문 회사 동일성 검증과 robots 리디렉션 규칙은 서로 다른 판단이다.

## 검증

인과성 부분 수정의 범위 고정, 수정 호출 장애, 감사 누락, 공급기업의 세부 적합성 탈락, 누락 이유·추가 후보, 고객 작성 글 제외, 템플릿·중복 주소, 다른 서버의 robots 규칙, 도착지 금지, 403·5xx, 요청 재시도 제한, 공개 API 읽기, 진단 PDF의 원문·비밀 값 제외를 회귀 테스트한다. 실제 검색창·모든 업무 선택·네이티브 다운로드로 14개 URL을 별도 재점검하고, 결과는 기존 62건 자료와 구분해 저장한다.

## 실제 1차 검증에서 추가로 확인해 반영한 원인

- 원문 인용의 `→`가 모델 출력에서 `–`로 바뀌어 기능 설명이 맞는 카드도 인용 검증에서 탈락했다. 공급기업 원문을 번호가 붙은 구간으로 제공하고 모델은 `source_span_id`만 선택한다. 서버가 실제 원문을 삽입하며, 독립 감사는 해당 구간이 카드의 핵심 기능을 뒷받침하는지도 확인한다. 원문과 유사한 문구를 임의로 참으로 처리하지 않는다. 필드별 로컬 검증 오류도 재작성 피드백과 진단에 남긴다.
- 한글 제품 경로와 검색어 공백이 HTTP 전송 전에 인코딩되지 않아 상품 페이지가 누락됐다. 공개 주소·포트·인증정보 검사를 유지하면서 경로와 검색어를 적절히 인코딩한다. 미완성 링크 매크로와 내용이 같은 페이지도 제외한다. 셀바티코 재수집에서 기존의 홈페이지·브랜드 소개 2종 외에 실제 제품·주문 안내 본문을 확보했다.
- 회사 홈페이지에 연결된 공식 카탈로그 PDF가 HTML 전용 수집에서 제외됐다. 같은 회사의 공개 링크, robots, 3MB 한도 안에서 읽고 최대 12쪽의 텍스트만 페이지별 출처로 사용한다. 암호화·손상·텍스트가 없는 문서는 꾸며 채우지 않는다. 숫자 등의 추출 실패 문자가 있는 인용도 사실 근거로 채택하지 않는다. 셀리코는 공식 카탈로그 8쪽을 확보했다.
- 가격과 구매 안내가 있는 공식 상품 제공 화면은 관찰된 온라인 상품 안내·판매 기능의 근거로 구분한다. 제조·연구·실제 거래량·내부 데이터의 근거로 확대하지 않는다.
- 최종 검증 중에는 `OSS_DIAGNOSTICS_COMPLETE=1`로 정상 결과의 내부 판정 근거도 기록한다. 기본값은 기존의 불완전 결과만 기록하는 정책이며, 정상 진단에도 공급기업 연락처 값은 저장하지 않는다. API 응답에는 내부 원본 초안이나 진단 파이프라인을 노출하지 않는다.

## 원래 요구 산출물의 일치 검사

동일한 이전 업무를 고정한 검증에서, 자료 누락·불일치를 점검하는 임상 업무에 대조군 예측을 제안해도 넓은 Task명만 보고 통과하는 경우를 확인했다. 카드가 원래 업무의 산출물 ID를 선택하도록 하고, 서버가 원래 문구를 연결한다. 별도의 `outputs_aligned` 검증에서 원래 메커니즘과 산출물 종류를 직접 지원하는지 확인한다. 담당자가 별개의 예측 결과를 받아 처음부터 점검표를 만드는 경우는 직접 지원으로 인정하지 않는다. 문서 검토를 시뮬레이션으로 바꾸거나, 출력 라벨만 복사해 통과시키지 않는다. 원래 산출물 ID 누락·변경과 산출물 감사 실패는 로컬 검증에서도 차단한다. 추가 실제 동일입력 재검증에서 레디큐어의 모델·실험 기록 비교에는 F039가 연결됐고, 문서 누락·불일치 검토에는 I590이 제외됐다.

산출물 일치는 원래 업무의 유용한 직접 구성요소를 지원하는지 검사한다. 한 업체가 모든 산출물·모든 부가 조건을 제공해야 한다는 뜻은 아니다. 예를 들어 실제 발주량 생성 기능이 있으면 근거 설명이나 공급 조건의 확인 범위를 분리해 제안할 수 있다. 이것과 문서 누락 점검을 별개 시뮬레이션으로 바꾸는 것은 구별한다. 감사에는 실제 제출한 카드의 쌍만 보내고, 요청하지 않은 쌍이나 중복 감사가 카드 통과 근거가 되지 않도록 한다.

## 잘못 고른 공급기업 제품·근거의 제한적 교정

셀바티코 실제 검색에서 같은 공급기업의 RAG/LLM 제품을 선택했지만 원문에는 별도의 BOT 상담 제품이 있어 잘못된 제품·근거 선택이 카드 탈락으로 이어졌다. 감사자가 원래 업무를 지원하는 같은 업체의 대체 제품명과 원문 구간 ID를 제시한 경우, 코드가 두 값이 실제 원문에 있는지 확인한 뒤 한 번만 교정한다. 고유 도메인 충돌은 교정 대상으로 삼지 않으며, 요구 메커니즘·산출물이 달라져야 하는 경우에도 교정을 허용하지 않는다. 교정된 카드도 모든 적합성·원문·산출물 감사를 다시 통과해야 표시한다. 업체에 실제로 없는 기능을 문장으로 만들어 재시도하는 흐름과 구분했다.

원래 탈락 카드를 고정한 별도 실제 재감사에서는 RAG/LLM의 답변 초안 기능은 인정됐지만, 원래 업무가 요구한 상품 근거 표시 기능은 확인되지 않아 탈락을 유지했다. 따라서 셀바티코의 해당 결과를 제품명 교정만으로 해결했다고 보고하지 않는다. 재감사·교정 후보가 없는 기능 부족은 출력 문구로 채우지 않는다. 모델의 의미 판정은 생성된 업무 범위와 공급기업 원문에 영향을 받으므로, 이전 업무 고정 검증과 새 검색 결과를 구분한다.

## 분류 태그를 배제 규칙으로 오해한 과업 감사

프레시스토어의 최신 탈락 사유는 N030의 `domains=제조`를 제조업 전용 제한으로 읽은 것이었다. 원본 과업의 목적은 ‘예상 수요에 맞춰 구매·재고를 결정’, 경계는 ‘예측 후 구매·재고 의사결정과 계획량을 산출하는 흐름’으로 소매 재고를 금지하지 않는다. 원본 과업표는 수정하지 않았다. 모델 전달 필드를 `catalog_domain_tags`로 구분하고, 분류 태그와 활동 예시가 배제 규칙·필수 전체 작업 목록이 아님을 명시했다. 목적·입출력·명시 경계에 있는 고유 도메인 제한은 유지한다. 같은 사업정보·매핑·평가문을 고정하고 실제 독립 감사만 다시 실행한 검증에서 N030이 통과했다.

## 상세 설명의 원문 번호 글꼴

모드하우스 보고서에서 공급기업 상세 원문의 ①②③ 번호가 Nanum 글꼴에 없어 누락되는 것을 실제 PDF 대조로 확인했다. 숫자 값이 보존되는 일반 숫자로 렌더링하도록 바꿨다. 원천 데이터나 화면 문구는 수정하지 않는다. 원문 전체를 정규화해 대조하고, 첨자·기호 및 감싼 숫자의 읽기 가능한 표시를 회귀 테스트한다.

## 직접적인 부분 지원과 다른 업무를 구분하는 판정

일부 실제 감사가 확인된 핵심 기능을 인정하면서도 ‘근거 표시’ 등 나머지 기능 전체가 확인되지 않았다는 이유로 카드를 모두 제외했다. 원래 업무의 구체적인 출력 구성요소를 공급기업이 직접 지원하는 경우를 `partial`로 구분했다. 원문·실제 기능·고유 도메인·유용한 업무 단계·정직성·안전·조건 공개가 모두 통과하고, 실제 지원 구성요소가 원래 산출물에 포함되며, 미지원 기능 1~3개가 명시돼야 채택한다. 임상 문서 점검 대신 예후 예측을 제안하는 등 다른 작업·출력 종류는 `adjacent`로 분류해 계속 제외한다. 원래 업무 목록·메커니즘·산출물을 바꾸지 않는다.

부분 지원 후보에는 화면과 PDF 모두 ‘일부 단계 지원 · 추가 확인 필요’, ‘지원 범위’, ‘미확인 기능’을 표시한다. 정상 판정은 사용자 기준대로 모든 업무에 실제 근거가 있는 공급기업과 필수 필드가 출력됐다는 뜻이며, 부분 후보의 미확인 기능까지 전부 검증됐다는 뜻은 아니다. 일부 지원 표시가 누락된 카드도 필드 점검에서 비정상으로 잡는다.

## 과업 ID만으로 후보가 닫히는 문제

등록·원천정보가 확인된 공급기업 설명에서 기능을 검색하는 경로를 추가했다. 같은 과업 ID의 후보를 우선 배치하고, 최대 12곳의 총 한도 안에서 일반 기능과 해당 회사 업무의 두 검색 결과를 교차 배치한다. 과업의 업종 태그는 검색 배제 조건으로 쓰지 않는다. 검색 점수는 적합성 점수가 아니며, 검색만으로 카드가 노출되지 않는다. 추가 후보는 `functional_candidate`·미검토 근거로 구별하고 동일한 원문·기능·도메인·안전·직접 구성요소 감사를 통과해야 표시한다. 기존 원본 과업표·공급기업 등록·Task 연결을 수정하거나 생성하지 않는다. 등록·원천정보가 확인되지 않은 업체를 검색으로 추가하지 않는다.

## robots 경로의 HTML 응답 오분류

오스의 대표 사이트는 robots.txt 경로에 회사 소개 HTML과 HTTP 200을 반환했다. 이를 네트워크 장애로 분류하지 않고 각 행에서 해석 가능한 규칙을 적용한다. HTML에 실제 Disallow 규칙이 포함된 경우에도 차단하는 회귀 검사를 추가했다. HTML 정책은 서버 간 캐시에 넣지 않는다. HTTP 5xx·접속 실패·본문 접근 거부는 계속 구별해 차단한다. 이는 [RFC 9309의 성공 응답·파싱 오류 처리](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.5)를 근거로 한 정책이며, 사이트의 올바른 robots 제공 여부와 수집 허용 판정을 구분한다.

## 최종 PDF의 한자 보조 글꼴

실제 모드하우스 검색의 생성 문장에 ‘担当자’가 포함됐고, Nanum에 없는 간체 한자 두 글자가 PDF에서 빠지는 것을 시각 대조로 발견했다. 임의로 단어를 바꾸지 않고 기본 글꼴에 없는 문자에 내장 보조 글꼴을 적용한다. 보조 글꼴은 Google Fonts의 OFL Noto Sans SC를 고정 굵기로 변환하고 기본 글꼴이 지원하는 문자를 제외한 배포용 파일이다. 원문 문자·PDF 텍스트 보존과 실제 보조 글꼴 내장을 검사한다. 최종 PDF 검증은 두 글꼴의 지원 범위를 대조하며, 지원되지 않는 문자를 제거한 뒤 통과시키지 않는다.

검색·추천 파이프라인을 다시 실행해 정상 결과를 고르는 대신, 동일 버전의 14개 실제 검색 응답을 보존한 뒤 글꼴 보완만 별도 반영한다. 실제 저장된 응답을 OSS 화면에 복원하고 원래 다운로드 요청 내용과 모든 필드를 대조한 뒤 다운로드 버튼으로 다시 받는다. 검색·진단 버전과 최종 PDF 버전은 보고서에 각각 기록한다. 검색 이후 변경 파일이 PDF·글꼴·패키징과 관련 검사에 한정되는지도 해시로 확인한다.
