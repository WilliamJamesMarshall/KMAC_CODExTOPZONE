# Supabase 배포 적합성 점검 · 2026-10-17

점검 시각: **2026-10-17 02:09~02:12 KST**. 연결된 Supabase 관리 도구, 읽기 전용 SQL, 실제 앱의 REST 조회 경로로 확인했다. 키 값·기업별 연락처는 보고서에 포함하지 않았다. 요금제·권한·데이터 변경, 인프라 생성은 수행하지 않았다.

## 결론

**현재 Supabase는 Free를 유지한 소규모 시범 배포에 적합하다. 지금 확인한 규모·상태만으로 Pro 전환이나 DB 이전을 할 필요는 없다.** 서울 리전에 정상 가동 중이고, 저장 용량에 여유가 있으며, 실제 서버 키를 사용하는 공급기업 조회도 성공했다.

다만 상시 운영의 가용성·백업 조건까지 충족했다고 볼 수는 없다. **Free의 비활성 일시중지 조건, 자동 백업 미포함, 이번 달 누적 전송량 미확인**이 남아 있다. 이 점검은 Supabase 측 준비 상태에 대한 판단이며, 전체 웹 앱의 운영 서버·Chromium 컨테이너 검증을 대신하지 않는다.

## 2. 보안·접근 상태

읽기 전용 시스템 카탈로그 조회로 다음을 확인했다.

- public의 **17개 테이블 모두 RLS 활성**.
- `anon`, `authenticated`의 모든 public 테이블에 대한 **SELECT·INSERT·UPDATE·DELETE 권한 없음**.
- `service_role`은 서버 조회에 필요한 SELECT 권한을 갖고 RLS를 우회하는 역할이다.
- public의 뷰·사용자 함수는 각각 0개.
- Storage 버킷은 비공개이며 Storage 정책은 0개.
- 로컬 Supabase 서버 키로 실제 REST 요청 성공.
- 현재 키의 실제 문자열은 Git 추적 파일 및 `web/` 파일에서 발견되지 않음. `.env`도 Git 비추적 상태.

키 검사는 현재 체크아웃과 현재 키 값에 한정한다. 과거 Git 이력·외부 로그·다른 키의 노출 여부까지 확인한 것은 아니다. 클라우드 배포 시에도 서버 비밀값으로 주입해야 한다.

## 4. 최근 로그

Supabase 로그 도구의 기본 최근 24시간 조회에서 다음이 반환됐다. 도구가 반환한 보존 범위의 로그에 한정하며 이번 달 전체 기록은 아니다.

- API 게이트웨이 `edge_logs`: **184건, 전부 HTTP 200**.
- PostgreSQL 로그: **9건, 전부 LOG 등급**.
- 연결 풀 로그: 11,590건 존재. 메시지별 원인 분석은 수행하지 않았고 오류 0건이라고 판정하지 않았다.

게이트웨이·PostgreSQL의 위 집계에서 4xx·5xx 또는 ERROR·FATAL은 나타나지 않았다. 짧은 보존 기간과 소규모 관측으로 미래 가용성을 보장할 수는 없다.

## 5. 무료 시범 운영 조건

### 전송량

현재 코드에서는 공급기업 인덱스를 재사용해도 각 조회의 풀 원문 응답이 약 **0.40MB** 발생한다. 매번 새 인스턴스에서 조회하면 약 **0.59MB**다. 월 1,000회라면 응답 본문만 약 **0.40~0.59GB**라는 단순 추정이 가능하다. 재시도·다른 API·DB 작업·프로토콜 오버헤드·실제 과금 집계는 포함하지 않았다.

**이번 달 누적 egress와 남은 무료 전송량은 현재 연결 도구에서 확인하지 못했다.** 새 데이터 수집·다른 클라이언트 트래픽까지 포함한 잔여량은 조직의 [Usage 화면](https://supabase.com/dashboard/org/ewjenfgqfdcfdcqrqdjf/usage)에서 확인해야 한다. 위 요청당 측정값을 월 누적 실측으로 대체하면 안 된다. [전송량 집계 설명](https://supabase.com/docs/guides/platform/manage-your-usage/egress)

현재 규모에서는 우선 전송량을 관측하면 된다. 늘어날 경우 필요한 원문 필드만 선택하거나 서버 캐시를 갱신 정책과 함께 도입할 수 있지만, 이번 점검에서는 코드를 변경하지 않았다.

### 일시중지와 백업

- Free는 **1주 비활성 시 프로젝트 일시중지** 조건이 있다. 현재는 활성 상태지만 장기간 사용하지 않은 후 시연할 때 상태를 확인해야 한다. [무료 조건](https://supabase.com/pricing)
- Free에는 **자동 백업이 포함되지 않는다**. 공개 시범 운영 전에 현재 DB를 외부로 내보내고 복구 절차를 확인하는 것이 필요하다. 기존 import SQL과 원문 스냅샷만으로 이후 변경분까지 복구된다고 가정하지 않는다. [공식 백업 안내](https://supabase.com/docs/guides/platform/backups)
- 상시 서비스에서 일시중지를 허용하기 어렵거나 자동 일일 백업이 필요해지면 Pro 전환을 검토한다. 저장 용량 부족 때문에 지금 즉시 유료화할 상황은 아니다.
